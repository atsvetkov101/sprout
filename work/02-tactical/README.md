# Этап 2 — Тактическое проектирование ядра

Цель: спроектировать богатую доменную модель (Rich Domain Model) для одного Core-контекста.

## Задачи

1. **Value Objects** — минимум 2 концепции как VO; реализация одного VO с проверкой инвариантов и структурным равенством.
2. **Entities & Aggregates** — спроектировать Корень Агрегата и внутренние сущности; реализовать агрегат: скрыть сеттеры, бизнес-метод изменения состояния, защищающий инварианты.
3. **Domain Services** — выявить бизнес-правило вне агрегатов; сигнатура/псевдокод доменного сервиса.

## Артефакты (план)

- `vo.md` / `src/vo/*` — объекты-значения.
- `entities.md` / `src/entities/*` — сущности.
- `aggregate.md` / `src/aggregates/*` — корень агрегата.
- `domain-service.md` / `src/services/*` — доменные сервисы.

См. также существующую доменную модель в `Tickets/src/Tickets.Domain/`.

### Полезные замечания
**Заявка** и **Работа над заявкой** имеют свои собственные команды и события. **Заявка** и **Работа над заявкой** соотносятся как 1 к n. Заявка может быть переоткрыта несколько раз, в результате будет несколько Работ над заявкой. В один момент времени Заявка связана с одной Работой над заявкой. Изменения в объекте Заявка применяются к объекту Работа над заявкой по событию. И в обратную сторону, изменения в объекте Работа над заявкой применяются к объекту Заявка так-же по событию.

**Заявка** имеет ссылку по идентификатору на **Работу над заявкой**. **Работа над заявкой** имеет ссылку по идентификатору на **Заявку**. **Заявка** - агрегат, **Работа над заявкой** - агрегат.
