# work/ — рабочая директория проекта «Система управления разъездными сотрудниками» (DDD)

Структура подкаталогов соответствует этапам проектной работы из `task.md`.

## Этапы

| Каталог             | Этап                                                        | Ключевые артефакты                                      |
|---------------------|-------------------------------------------------------------|---------------------------------------------------------|
| `work/01-strategic/`    | Этап 1 — Стратегическое проектирование                  | субдомены, глоссарий, карта контекстов                  |
| `work/02-tactical/`     | Этап 2 — Тактическое проектирование ядра                | VO, сущности, агрегаты, доменные сервисы (код)         |
| `work/03-architecture/` | Этап 3 — Архитектура приложения и паттерны              | гексагон, репозитории, фабрики, CQRS, BFF              |
| `work/04-async/`        | Этап 4 — Асинхронность, БД и интеграция                 | доменные/интеграционные события, Outbox, Saga, DDL     |
| `work/05-observability/`| Этап 5 — Наблюдаемость и деплой                        | логи/трассировка, миграция Expand-Contract              |
| `work/06-extra/`        | Задание со звёздочкой (опционально)                    | Docker Compose, Outbox Worker, мониторинг               |

## Сопутствующие файлы

- `task.md` — текст ТЗ (проектная работа).
- `.codeassistantignore.example` — пример ignore-файла для ассистента.

## Примечание

Исходный код Тактического проектирования (Этап 2 и часть Этапа 3) согласно формату
сдачи должен находиться в `src/`. Внутри подкаталогов этапов удобно размещать
описательную документацию, а код — в `src/` либо в отдельных пакетах каждого этапа
(например, `work/02-tactical/src/`).
