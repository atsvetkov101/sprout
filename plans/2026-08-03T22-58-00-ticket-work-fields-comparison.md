# Поля объекта «Работа над заявкой» (TicketWork)

## Требуемые поля

| Поле | Описание |
|------|----------|
| `id` | Идентификатор |
| `status` | Статус работы над заявкой: «в маршруте» / «в работе» / «выполнена» / «отменена» и др. |
| `plannedOrder` | Порядковый номер в маршруте |
| `start_date` | Дата/время начала работы над заявкой |
| `service` | Категория заявки |
| `user_events` | Пользовательские события |
| `coords_list` | Координаты |
| `act_id` | Идентификатор акта (если есть) |

---

## Сравнение с текущей реализацией

Текущая реализация: [`Tickets/src/Tickets.Domain/entities/ticket-work.ts`](../Tickets/src/Tickets.Domain/entities/ticket-work.ts)

### Поля текущей реализации

| Поле | Тип | Наличие в требованиях | Комментарий |
|------|-----|----------------------|-------------|
| `id` | `string` | ✅ есть | Совпадает с требуемым `id` |
| `status` | `string` | ✅ есть | Совпадает с требуемым `status` |
| `deadline` | `Date` | ❌ нет | Дедлайн — не входит в список требуемых полей |
| `act_type` | `string` | ⚠️ частично | Есть `act_type` (тип акта), но требуется `act_id` (идентификатор акта) |
| `wiki_link` | `string` | ❌ нет | Ссылка на вики — не входит в список требуемых полей |
| `events` | `DomainEvent[]` | ⚠️ частично | Есть доменные события, но требуется `user_events` (пользовательские события) |

### Сопоставление требуемых полей с текущей реализацией

| Требуемое поле | Есть в реализации? | Статус |
|----------------|--------------------|--------|
| `id` | ✅ `id` | Совпадает |
| `status` | ✅ `status` | Совпадает |
| `plannedOrder` | ❌ отсутствует | **Отсутствует** — нет поля порядкового номера в маршруте |
| `start_date` | ❌ отсутствует | **Отсутствует** — есть только `deadline`, но нет даты начала работы |
| `service` | ⚠️ частично | В текущей сущности `service` упоминается в `fromDb`/`setService`, но не объявлено как поле класса |
| `user_events` | ❌ отсутствует | **Отсутствует** — есть только `events` (доменные события) |
| `coords_list` | ❌ отсутствует | **Отсутствует** — координат в сущности нет |
| `act_id` | ⚠️ частично | Есть `act_type`, но нет `act_id` |

### Итог

| Категория | Поля |
|-----------|------|
| ✅ Полностью совпадают | `id`, `status` |
| ⚠️ Частично совпадают | `service`, `act_id` (есть `act_type`) |
| ❌ Отсутствуют в реализации | `plannedOrder`, `start_date`, `user_events`, `coords_list` |

### Замечания

1. **`plannedOrder`** — отсутствует. Нужно добавить поле порядкового номера в маршруте.
2. **`start_date`** — отсутствует. В текущей реализации есть только `deadline`, но нет даты начала работы над заявкой.
3. **`user_events`** — отсутствует. В текущей реализации есть `events` (доменные события `DomainEvent[]`), но это не пользовательские события.
4. **`coords_list`** — отсутствует. Координаты в сущности не хранятся.
5. **`act_id`** — в текущей реализации есть `act_type` (тип акта), но нет идентификатора акта `act_id`.
6. **`service`** — используется в методах (`fromDb`, `setService`), но не объявлено как поле класса.
7. **`deadline`** и **`wiki_link`** — присутствуют в текущей реализации, но не входят в список требуемых полей.
